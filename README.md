# Отбор вин

Приложение использует лабораторные показатели, чтобы оценить вероятность качества не ниже 7 баллов. Модель — `StandardScaler` и `LogisticRegression`. Порог по умолчанию сохранён в `config.json`: примерно 0.23636. Он выбран на валидации внутри train: максимальный precision при recall не ниже 0.7.

## Локальный запуск

Проверено на Python **3.12.0**. Подойдёт Python 3.12 с установленными зависимостями из `requirements.txt`.

Откройте терминал в папке `wine_app` и выполните:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

В Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate`. Если Python 3.12 вызывается командой `python` или `python3`, используйте её вместо `python3.12` в первой строке.

Откройте адрес, который напечатает Streamlit, обычно `http://localhost:8501`. Модель уже обучена; заново запускать ноутбук для работы приложения не нужно. Файлы читаются относительно `app.py`, поэтому приложение можно запускать из другой папки, указав путь к скрипту.

## Файлы

- `app.py` — интерфейс и предсказания;
- `model.joblib` — обученный пайплайн, включая масштабирование;
- `config.json` — выбранный по валидации порог;
- `test.csv` — неизменённая тестовая выборка после исходного разбиения;
- `requirements.txt` — версии зависимостей;
- `.streamlit/config.toml` — оформление.

В ноутбуке полные дубли исходного набора удалены до разбиения, чтобы одинаковые наблюдения не попадали в train и test. После этого train содержит 3724 строки, test — 1596. Параметры масштабирования и модели вычислены только по train. При выбранном пороге на test получены precision 0.4213, recall 0.7063 и F1 0.5277. Это оценка на одном разбиении, а не гарантия качества для любого нового набора.

## Вкладки

«Одно вино» принимает 11 числовых показателей и цвет вина. Диапазоны и начальные значения взяты из `test.csv`. Вероятность сравнивается с общим порогом в боковой панели.

«Модельные метрики» показывает precision, recall, F1, долю отобранных вин, матрицу ошибок, ROC- и PR-кривые. Точки на кривых соответствуют текущему порогу. Больший порог уменьшает подборку и recall; меньший расширяет подборку и допускает больше обычных вин.

«Загрузка CSV» принимает файл с разделителем-запятой и следующими столбцами:

```text
fixed_acidity,volatile_acidity,citric_acid,residual_sugar,chlorides,free_sulfur_dioxide,total_sulfur_dioxide,density,pH,sulphates,alcohol,is_red
```

Порядок столбцов может отличаться: перед прогнозом приложение восстановит порядок обучения. В `is_red` используются 0 для белого и 1 для красного вина. Столбец `target` не нужен. На вкладке можно скачать пример файла и таблицу с колонками `probability_good` и `recommend`. Пропущенные столбцы, пустые файлы, пропуски и нечисловые значения вызывают понятное сообщение об ошибке.

«Что выучила модель» показывает коэффициенты после масштабирования. Их знак относится к изменению одного признака при фиксированных остальных; причинного влияния он не доказывает.

## Зачем нужен кэш

`load_model` использует `st.cache_resource`: один объект модели разделяется между повторными запусками скрипта и сеансами. Приложение этот объект не изменяет. Без декоратора `joblib.load` читал бы файл и создавал новый объект при каждом движении ползунка.

`load_test` и `test_proba` используют `st.cache_data`: таблица и массив вероятностей — данные, для которых Streamlit возвращает копию результата. Аргумент `_model` исключён из хеширования. Когда меняется только порог, `predict_proba` для test повторно не вызывается: меняются метки и зависимые от них метрики. Модель и данные считаются неизменными в течение работы сервера; после замены файлов сервер нужно перезапустить. Различие декораторов описано в [документации Streamlit](https://docs.streamlit.io/develop/concepts/architecture/caching).

## Публикация в Streamlit Community Cloud

1. Создайте репозиторий на GitHub и загрузите в его корень **содержимое** папки `wine_app`, включая `.streamlit`, `model.joblib`, `config.json`, `test.csv` и `requirements.txt`. Папка окружения `.venv` в репозиторий не нужна.
2. Войдите в [Streamlit Community Cloud](https://share.streamlit.io/) и подключите GitHub.
3. Нажмите **Create app**, выберите свой репозиторий и ветку. В поле главного файла укажите `app.py`.
4. В **Advanced settings** выберите **Python 3.12**, сохраните настройки и нажмите **Deploy**.
5. Дождитесь появления приложения и проверьте вкладки. Добавьте полученную ссылку в ячейку задания 4.6 ноутбука.

Если в репозиторий загружена сама папка `wine_app`, укажите главный файл `wine_app/app.py`; файл зависимостей должен лежать рядом с ним. Пошаговая процедура есть в [инструкции Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

Данные: [Wine Quality, UCI](https://archive.ics.uci.edu/dataset/186/wine+quality), P. Cortez et al., 2009, CC BY 4.0. CSV с бинарным таргетом взят из материалов курса ММАД.
